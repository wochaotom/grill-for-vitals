# Vitals Source Matrix

Use this matrix to keep the skill specialized. It maps each vital to likely source activations and evidence gates. Do not treat a source preset as required unless the vital actually exists in the system under review.

| Vital | Activate sources when | Useful presets or source IDs | Evidence gates |
|---|---|---|---|
| Secrets/control plane | Credentials, cloud IAM, PIM, service principals, MDM/MAM, or endpoint-management roles can deploy, administer identity, read tenants, sign, wipe devices, or move money | `control-plane-supply-chain`, `nist-ssdf`, `cisa-secure-by-design` | Secret inventory, IAM/role graph, PIM activation, storage boundary, log/tracing exclusion, rotation/revocation, CI permission scope |
| Identity/auth/sessions/tenancy | Login, recovery, federation, admin access, API auth, RLS, tenant boundaries, BOLA/IDOR/BFLA, object/function-level authorization | `identity-auth`, `nist-sp-800-63-4`, `owasp-asvs`, `owasp-api-top10` | Server authz, tenant/object ownership checks, admin gate, session settings, cross-tenant and per-object negative tests |
| PII/customer content | Raw prompts, uploads, transcripts, URLs, model I/O, customer files, object storage/signed URLs, mobile local storage, sensitive records, HR/legal records, financial records, CUI/government data, DSAR/ROPA/DPIA/retention/consent/cross-border/vendor privacy surfaces | `privacy-customer-content`; conditional `financial-customer-data`, `health-ephi`, `child-privacy`, `biometric-identity`, `federal-defense` | Data inventory, minimization, retention schedule, deletion/export, rights workflow, log allowlist, object/mobile-storage controls, processor/model boundary |
| Money/billing/trading/procurement | Charge, refund, quota, trade, transfer, stake, bid, buy, or commit | `payments-cardholder` or `pci-dss` for card/payment data; `sanctions-export` for virtual currency, cross-border, sanctions, or export triggers; `payments-sanctions-export` only when combined | Webhook truth, signature checks, idempotency, human gate, risk limits, sanctions/export trigger flag |
| Irreversible mutation | Deletes, migrations, overwrites, production jobs, durable transitions | No default external source; use local evidence first | Preview/dry-run, scope, confirmation, backup, rollback/compensation, rehearsal tests |
| External effects | Email, SMS, chat, PR merge, release, publish, file, submit, bid, webhook, physical or safety-critical action | `safety-ot` for OT/physical-control systems; `incident-recovery` when incident/recovery matters; current official domain authorities for regulated safety domains | Draft/send separation, human approval, destination/payload/actor/source log, correction path, fail-safe/stop path |
| Agent/tool/MCP/browser/shell | Tools can read private data, mutate, spend, send, install, browse, run shell, or schedule | `agentic-llm`, `mcp-tooling`, `ai-review-toolchain`, `mcp-security-best-practices`, `owasp-agentic-apps`, `owasp-agentic-skills`, `mitre-atlas` | Tool registry, action classes, permission scope, sandbox, audit outside actor, human gate for high-risk action |
| Supply chain/build/deploy | Privileged CI/CD, packages, artifacts, model/package source, release/publish, Kubernetes/RBAC/service accounts, cloud IAM, MDM/MAM policy, IaC plans/scanners | `control-plane-supply-chain`, `mitre-cwe-top25` after a vital path is found | Pin/review privileged code, scoped CI tokens, artifact provenance/signing, deploy approval, plan/manifest/RBAC/IAM evidence |
| File ingress/storage | Uploads, parsers, OCR, URLs, object storage, temp files, signed URLs | `owasp-asvs`, `owasp-api-top10`, privacy sources when content is sensitive | Size/type/path checks, SSRF controls, parser sandbox, tenant ownership, public-access blocks, signed URL limits, temp-file cleanup |
| Logs/audit/evidence | Logs, traces, analytics, model/tool traces, audit tables, incident records, endpoint/EDR/DLP telemetry, ransomware/recovery evidence, breach notification clock, chain of custody, honeytokens/canaries | `incident-recovery`, privacy sources when sensitive data appears | Secret/PII exclusion, denied-action logs, immutable/external audit, incident reconstruction detail, endpoint tamper resistance, restore-test and evidence-preservation proof |
| High-trust outputs | Health, legal, financial, tax, compliance, benefits, employment, housing, safety, automated decisions or profiling with significant effects | `high-trust-output`; add `agentic-llm` when LLM/tool/RAG risk is the driver; current official domain authorities activated during the run | Authoritative source corpus with checked date, source-set logging, refusal/escalation, qualified human review, meaningful intervention/contestation |
| Cost/availability/runaway loops | Model calls, retries, fanout, queues, jobs, spend, external rate limits, GraphQL depth/query complexity, API enumeration | `cost-availability`; add `agentic-llm` when model or agent loops are the driver | Rate/usage caps, retry bounds, queue/fanout limits, query depth/complexity limits, timeout/cancel, kill switch, monitoring owner |

## Matrix Rules

- Prefer local evidence before source activation.
- Use source presets to pick questions, not to produce compliance labels.
- If a finding does not map to a row, it is probably a out-of-scope handoff unless the user names a catastrophic failure mode.
